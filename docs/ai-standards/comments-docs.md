# Comments And Docs

## 语言

内部注释与文档注释统一使用**中文**（专有名词、标识符、错误码除外）。

## 文档注释（`///` 与 `//!`）

- 每个 crate 的 `lib.rs` 顶部用 `//!` 写一段说明：这一层是什么、依赖谁、不该做什么
- **每个公共项**（`pub` 的函数、类型、字段、枚举变体、trait、模块）必须有 `///`；工作区启用了 `missing_docs = "warn"`，`just lint` 里警告即失败
- 第一句话说明「它是什么 / 做什么」，要完整、简短；细节另起段落
- 返回 `Result` 的公共函数写 `# Errors`，说明什么情况下会失败
- 可能 panic 的公共函数写 `# Panics`
- 有 `unsafe` 的地方必须写 `// SAFETY:` 说明为什么安全（工作区默认 `forbid(unsafe_code)`，要用先讨论）

```rust
/// 创建 PostgreSQL 连接池。
///
/// 连接是**惰性**建立的：数据库暂时不可用时服务照常启动，由 `/ready` 如实报告。
///
/// # Errors
///
/// 连接串无法解析时返回错误。
pub fn connect_lazy(...) -> Result<PgPool, sqlx::Error> { ... }
```

## 普通注释（`//`）

- 解释**为什么**这样写，而不是复述**做了什么**；好代码自己说明做了什么
- 值得写的注释：不显然的约束、对依赖行为的假设、性能或安全上的取舍、临时绕过及其退出条件
- 不要留下被注释掉的代码；需要留存历史看 Git
- `TODO` / `FIXME` 必须带上下文（谁来做、为什么、什么条件下做）。工作区对 `todo!()` 宏会发出警告

## 抑制 lint 必须写理由

用 `#[allow(...)]` 时必须带 `reason`：

```rust
#[allow(clippy::result_large_err, reason = "闭包签名由 figment 决定，我们改不了")]
```

## 第三方行为的断言

文档和注释里描述依赖库行为的句子（「会不会读取某环境变量」「传空值与省略是否等价」）必须对照 `Cargo.lock` 锁定版本的源码或文档核实；拿不准就写个测试实测。这类断言最容易随依赖升级悄悄失效，错了还会误导安全判断。

## 文本编码

所有 Markdown、源码、配置文件使用 UTF-8（无 BOM）。
